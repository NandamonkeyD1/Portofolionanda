ELFAN Command Engine

A hardware automation architecture driven by microcontrollers (ESP32 / Raspberry Pi) with an MQTT pub/sub pipeline for sensor telemetry and precision relay control.

01 / Project Overview

ELFAN Command Engine is an autonomous hardware-to-cloud bridge engineered to connect edge microcontroller nodes with web-based operational dashboards. Leveraging the ultra-lightweight MQTT publish/subscribe protocol, it manages sensor telemetry streams and executes relay triggers with minimal network overhead.

02 / Problem & Motivation

Conventional consumer smart device setups frequently experience significant latency due to slow HTTP polling, forced dependence on third-party proprietary clouds, and a complete loss of local control whenever public internet connectivity suffers an outage.

03 / My Role & Contributions

As Embedded & Creative Technology Developer on this project:

  • Wrote low-level C++ firmware on the ESP32 handling WiFi reconnection state machines, JSON payload parsing, and hardware failsafe timeouts.
  • Configured a local Mosquitto MQTT broker and custom Node.js system daemon on a Raspberry Pi host.
  • Engineered a responsive telemetry web dashboard with WebSockets achieving sub-40ms visual feedback.
  • Conducted load tolerance and electrical isolation tests on 4-channel optocoupled relay arrays.

04 / Technical Stack

ESP32 (Dual Core 240MHz) Raspberry Pi (Linux Host) MQTT Protocol (Pub/Sub) C++ (Arduino Framework) Node.js Gateway WebSockets (Socket.io) Optocoupled Relays

05 / Design & Architecture Decisions

The system is architected in three decoupled layers:

  1. Edge Hardware Layer: ESP32 nodes read analog temperature/voltage sensors and actuate physical relay switches via GPIO pins.
  2. Gateway Host Layer: The Raspberry Pi runs a dedicated MQTT broker locally, ensuring scheduled automation rules remain fully operational even during complete WAN disconnection.
  3. Presentation Layer: A web interface receives real-time telemetry streams via push WebSockets rather than polling.

06 / Implemented vs Experimental Lab Features

To uphold technical integrity, the status of verified operational capabilities is distinguished from ongoing laboratory exploration below:

● Implemented & Verified

  • ESP32 firmware with automatic local WiFi reconnect routines.
  • MQTT Pub/Sub commands for 4-channel GPIO relay actuation with state verification.
  • Web-based telemetry monitoring with live sensor feeds.
  • Local historical activity and event logging on Raspberry Pi.

○ In Progress / Research Lab

  • Multi-node mesh synchronization (ESP-NOW to MQTT Gateway).
  • Edge-based power consumption anomaly detection algorithms.
  • End-to-end TLS payload encryption over public domains.

07 / Challenges & Lessons Learned

The foremost hurdle was electromagnetic interference (EMI) generated by mechanical relay coils, which initially triggered spurious resets on the microcontroller. We resolved this by physically isolating logic power rails from coil power rails using optocouplers and flyback suppression diodes.

08 / Outcome & Project Status

The core command prototype demonstrated dependable uptime throughout extended laboratory stress testing, serving as a core foundation for my research in creative technology and cyber-physical systems.
